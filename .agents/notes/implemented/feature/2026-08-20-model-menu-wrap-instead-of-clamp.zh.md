# Agent Note：模型菜单行改为换行而非截断文本

Status: implemented

[English](2026-08-20-model-menu-wrap-instead-of-clamp.md) | 中文

## 问题

输入框模型菜单（`packages/client/ui-model-selection`，`conversation.input.model` 座位的两级「模型/思考强度」下拉）把每一行文本都钳制为单行加省略号，菜单宽度只有 240px：长模型名丢失尾部，而作为行间主要区分信息的模型描述被截成几个字符。根面板的值单元格还可能一直伸长，直到左侧标签失去空间。输入框工具行里的触发芯片与强度后缀共享宽度，因此在窄卡片上模型名最先被省略。

菜单加宽到 320px 后，在手机上又暴露出一个定位问题：菜单以 `right: 0` 锚定触发芯片，而窄输入框卡片上的触发芯片位于行的中间（发送按钮占据行右端），于是菜单左缘跑出视口——在 360px 视口下触发芯片右缘在 x=281，菜单却宽 330px，左缘落在 x=-49。只有模型名的右侧切片（"…seek"）可见，多出的宽度在菜单右侧表现为一片空白。仅按视口钳制仍然不对：菜单位于输入框座位内部，其滚动体在水平方向裁剪（`overflow-x: hidden`），裁切框比视口更窄——360px 时座位横跨 x=56..360（304px），于是无论视口钳制把菜单放到哪里，330px 宽的菜单都会在座位的左缘被裁掉，即使钳制已把菜单拉回屏幕内，名字开头的字符（"Deep…"）仍然不可见。

## 决策

菜单不再截断任何行：

- 菜单宽度由 `min(240px, calc(100vw - 32px))` 加宽到 `min(320px, calc(100vw - 32px))`；宽度上限只把菜单约束在卡片范围内，再叠加一个 `useLayoutEffect` 定位流程（与 `ui-primitives` 中 Menu 原语的 portal 定位相同的「测量并钳制」模式）：菜单打开期间用实测 `left` 覆盖 CSS 的 `right: 0` 锚点。钳制框是最近的水平溢出非 visible 的祖先——手机上即输入框座位的滚动体，无任何裁剪时（jsdom 测试与桌面）则回退为视口——让两条边都保持在钳制框内 12px，而不只是视口。当 320px 的设计宽度放不进钳制框（360px 的座位约 304px）时，该流程还会把菜单的内联宽度（配合 `box-sizing: border-box`）收窄到钳制框减去两个边距，使菜单的任一部分都不会被座位裁掉。菜单打开期间在 `resize` 时重新定位；无需钳制时解析结果与 CSS 原本的右对齐位置一致。
- `.modelName` 与 `.description` 去掉 `white-space: nowrap` / `text-overflow: ellipsis`，改为自由换行（`overflow-wrap: break-word`）。长行会撑高选项；菜单既有的 `max-height` 上限把超出部分转为滚动，因此不丢失任何内容。
- 根面板的 `.cellValue` 保留单行省略号（该行是固定高度的骨架行），但加上 `max-width: 50%`，让左侧标签与右箭头保住空间，同时「模型」单元格以 `title` 携带完整值。
- 输入框卡片窄于 460px 时（InputBar 工具行的匿名 inline-size 容器，与 PermissionSelect 使用的查询相同），触发芯片隐藏强度后缀，把宽度让给模型名——芯片的身份信息。强度在菜单与触发芯片的 `aria-label`/`title` 中仍然可见。

触发芯片不再有固定宽度上限：它按内容自然定宽，输入框行收紧时先由工具组让位（其容器查询折叠相邻芯片），触发芯片的省略号只在行真正放不下时作为最后手段生效——无论哪种情况 `title` 都携带完整标签。必须展示完整文本的表面是菜单。

## 备选方案

**描述用两行钳制（`-webkit-line-clamp: 2`）。** 否决：无论钳到几行都会隐藏菜单本应展示的文本；高度上限加滚动已经约束了长列表，而行的换行高度与内容等高。

**模型名中间截断。** 否决：展示的是显示名而非机器 id，承载区分信息的尾部绝不能截掉；换行严格更完整，且无需测量。

**窄卡片上把整个芯片折叠为纯图标。** 否决：与权限芯片不同，模型座位没有图形身份——名字本身就是整个控件，因此必须保留文字，改为让强度后缀让位。

**保留 220px 的触发芯片上限。** 否决：该上限即使在行内还有空余时也会截断模型名；去掉它让芯片按内容自然定宽，先由工具组的容器查询吸收挤压。

## 后果

模型/强度列表中的行由固定高度变为内容自适应高度，粘性分组标题与可滚动的 `.groups` 本就兼容。菜单打开期间会带内联样式（覆盖的 `left`/`right`，座位过窄时还有配合 `box-sizing: border-box` 的收窄 `width`）和一个随打开状态销毁的 `resize` 监听器。没有改动任何语言文案、slot 契约或 store 数据；DOM 上的新增是根面板「模型」单元格的 `title` 与菜单的内联定位与宽度。同样的「换行代替截断」模式可作为其他仍在截断的菜单行的参照（轨迹表格保留其横向滚动契约，那是另一种阅读模式）。

## 测试

`packages/client/ui-model-selection/tests/model-select.client.spec.tsx` 固化菜单的用户可见行为，其中包括一条定位 spec（与 `ui-primitives` 中 tooltip 钳制 spec 相同的技巧，stub 触发芯片矩形与视口宽度）：触发芯片位于行中间、视口 360px 时，打开菜单的内联 `left` 让两条边都保持在钳制框内；一次 `resize` 重定位在触发芯片不再贴近边缘时释放钳制。另一条 spec 模拟手机座位：给根元素的父级设置真实的 `overflow-x: hidden` 样式与更窄的矩形，断言菜单收窄到座位减去边距（`box-sizing: border-box`）并在重排时重新调整尺寸。可见 UI 变更的组合式浏览器检查仍为 CI 中的 `DSH_SNAPSHOT=replay pnpm run test:web`；该检查无法在 Android/Termux 开发主机上运行，因为 Playwright 未为该平台提供浏览器构建。
