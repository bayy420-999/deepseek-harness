# Agent Note：设置面板在手机宽度上纵向堆叠导航与内容

Status: implemented

[English](2026-08-20-settings-panel-stacks-on-phones.md) | 中文

## 问题

设置外壳（`packages/client/ui-settings-general`，`SettingsRoot`）把面板渲染为固定的双栏模态框：188px 导航栏加内容栏，面板宽 800px、上限为 `calc(100vw - 48px)`。手机上该上限只剩约 342px，固定导航栏吃掉其中 188px——承载实际设置页（通用、模型、插件）的内容栏只有约 150px 宽。任何页面在这个宽度下都不可读；面板高度（`100vh`）同样无视移动端浏览器边框对底边的遮挡。

## 决策

720px 以下（ui-layout 的 `MOBILE_OVERLAY_MAX`，与框架和会话头部相同的断点）面板改为纵向堆叠：

- `.panel` 变为纵向：导航渲染在内容上方、通栏宽度。更紧的留白（`calc(100vw - 32px)`）加上 `@supports` 下的 `calc(100dvh - 32px)`，让面板在移动端浏览器边框下保持完整可见。
- 导航变为横向标签条：`.navList` 横向流动，单元格收缩为 36px 高的标签（`flex: none`，标签不随省略号生长），标签超出宽度时条带横向滚动。共享滚动条重绑定（`--dsh-scrollbar-thumb: transparent`）让条带的滚动条不可见，且不改变标签布局。
- `.navTitle` 在手机上隐藏——面板头部与当前标签已携带上下文，标题行会占用页面需要的纵向空间。
- 内容头部收紧到 46px，`.options` 左右内边距降到 16px，页面获得全部剩余宽度。

桌面几何不变；各分区页面无需改动（模型页的新增操作本就会折行，插件清单在 680px 以下已把卡片改为单列）。

## 备选方案

**在手机上把导航折叠为汉堡菜单/下拉。** 否决：四个分区足够放进一条横向滚动条，钻入式菜单要多点一次且不省宽度；条带与导航栏一样让每个分区一次点按可达。

**缩小导航栏而不是堆叠。** 否决：纯图标标签仍要占约 48px，而标签（分区名）就是导航本身；堆叠让内容获得完整宽度，这才是真正的缺口。

**让面板完全贴边。** 否决：16px 留白保持模态框相对背后对话的悬浮层次，也与应用其他手机宽度留白一致。

## 后果

面板的堆叠顺序仅在 720px 以下改变；导航行、slot 座位、关闭路径（头部按钮、遮罩点击、Escape）与分区渲染契约均不受影响。条带的横向滚动是唯一新增手势，且只在标签确实超出宽度时出现。这是移动端可读性系列（框架覆盖层模式、[头部面包屑](2026-08-20-header-crumbs-keep-the-current-title.md)、[去截断](2026-08-20-model-menu-wrap-instead-of-clamp.md)）在设置表面的延续。

## 测试

`packages/client/ui-settings-general` 套件（44 例）无需修改即通过：变更仅涉及 CSS，各 spec 断言的是分区内容、slot 座位与关闭行为，而非面板几何。可见 UI 变更的组合式浏览器检查仍为 CI 中的 `DSH_SNAPSHOT=replay pnpm run test:web`；该检查无法在 Android/Termux 开发主机上运行，因为 Playwright 未为该平台提供浏览器构建。
