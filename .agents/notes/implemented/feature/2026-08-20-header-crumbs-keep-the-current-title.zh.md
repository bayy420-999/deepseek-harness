# Agent Note：头部面包屑保持当前会话标题不被截断

Status: implemented

[English](2026-08-20-header-crumbs-keep-the-current-title.md) | 中文

## 问题

会话头部（`packages/client/ui-conversation`，`ConversationSession` 的头部骨架）的面包屑链把每一段面包屑都限制在 220px 并单行省略——包括标识当前会话的当前标题段。较长的会话标题即使列内还有数百像素空余，也会在 220px 处被省略；在手机宽度列上，140px 的移动端上限进一步压缩它。祖先段（子代理父级导航）固然是次要的，但行的 `overflow: hidden` 加固定上限意味着被切掉的恰恰是链尾——当前标题。此外，没有任何面包屑携带 `title`，被截断的文本无从查看。

## 决策

面包屑行现在按以下顺序保证当前标题的空间：

- 宽度上限从按钮移到其段落（`.crumbSeg`，分隔符 `/` 也在其中），且只有祖先段携带上限：桌面 220px，720px 及以下 140px。`.crumbSeg:last-child` 没有上限，因此当前标题使用行内剩余空间，而不是固定宽度。
- 按钮填满其段落（`width: 100%`、`min-width: 0`），使省略号跟随段落的实际宽度；祖先段以三倍速度让位（`:not(:last-child)` 上 `flex-shrink: 3`），因此标题在链被压缩殆尽之前保持完整文字。
- 每个面包屑按钮现在以 `title` 携带完整文本（原生提示），因此确实被截断的祖先段仍可完整阅读；裸的 sessionId 兜底 span 获得与其所替代按钮相同的收缩/省略处理。

祖先段的省略是刻意保留的：它们是子代理父链的导航控件，其完整文本现在可通过提示查看。当前标题只在头部确实没有空间时，作为行的最后手段才省略。

## 备选方案

**用 `direction: rtl` 截头留尾。** 否决：会翻转链的视觉阅读顺序，`/` 分隔符将倒读（当前 / 父级，而非父级 / 当前），而祖先顺序正是导航的语义。

**面包屑行横向滚动。** 否决：可滚动的面包屑把父级藏在手势后面，且与头部固定的两行几何冲突；祖先收缩加提示让整条链保持可见可达。

**把链折行到头部第二行。** 否决：头部第二行是视图标签页的位置；为长名字让出它会牵动整列重排，而上述方案保持几何稳定。

**统一放开所有面包屑的上限。** 否决：祖先段会在手机列上挤占当前标题的空间；收缩权重表达的正是设计真正的优先级。

## 后果

头部几何不变：行仍不折行、不滚动，标签页行保持其位置，[移动端覆盖层布局说明](2026-08-20-mobile-overlay-layout-mode.md)中的移动端头部内边距不受影响。DOM 上仅新增面包屑的 `title`。至此完成了[模型菜单说明](2026-08-20-model-menu-wrap-instead-of-clamp.md)开启的「去截断」模式：标识性表面（当前标题、模型名）优先获得宽度，次级骨架在标识文字之前让位。

## 测试

`packages/client/ui-conversation/tests/skeleton.client.spec.tsx` 已固化面包屑内容（当前会话重标注用例）且无需修改即通过——本变更仅涉及呈现层。可见 UI 变更的组合式浏览器检查仍为 CI 中的 `DSH_SNAPSHOT=replay pnpm run test:web`；该检查无法在 Android/Termux 开发主机上运行，因为 Playwright 未为该平台提供浏览器构建。
